您正在开发 API 服务器模块 (SigbotAPIServer)。该微服务为 SigBot 提供统一的 CRUD API 能力。

**架构与职责**：
- **2.1.1 API 服务器**：为所有 SigBot 资源提供统一的 API CRUD 能力
- 作为外部客户端（包括 sigbot-researcher）的主要入口点
- 提供用于管理策略、订单、钱包、回测等的 REST API
- 支持多租户架构

**主要职责**：
1. **REST API 端点**：
   - 为所有资源提供 CRUD 操作
   - 支持资源过滤、分页、排序
   - 在需要时处理文件上传/下载
   - 支持批量操作

2. **多租户支持**：
   - 从请求中提取 tenant_id（JWT、headers、path）
   - 按租户隔离数据
   - 验证租户访问权限
   - 支持租户特定配置
   
   **租户加密密钥管理**（用于独占租户）：
   - 每个独占租户都有自己的 RSA 密钥对（2048 位）用于加密敏感数据
   - 密钥对可以是用户提供的（导入）或在租户创建时系统生成的
   - 公钥存储在数据库中，私钥哈希用于验证
   - **云托管密钥（默认启用）**：为防止因丢失私钥导致的数据丢失，系统默认启用云托管密钥存储：
     - 私钥使用系统主密钥（AES-256-GCM）加密并安全存储
     - 系统主密钥从 `SIGBOT_SYSTEM_MASTER_KEY` 环境变量获取，或回退到 JWT secret
     - 用户可以通过设置 `cloud_managed_key: false` 显式禁用云管理
     - 启用云管理时，私钥被加密并存储在 `encrypted_private_key` 字段中
     - 这确保了用户丢失私钥时的恢复能力
   
   **租户组件配置**：
   - 所有租户级别的组件部署（中间件 + 微服务）将配置存储在 `tenant.components` 字段中
   - 组件配置包括：实例信息、连接地址、加密密码、性能参数
   - 密码在存储前使用租户的公钥加密
   - 组件类型：EMQX、PostgreSQL、TimescaleDB、Redis、Datafeed、Strategy、Notification、Backtest 子服务等
   - 每个组件实例存储：
     - 组件类型、名称、部署模式（standalone/cluster）
     - 连接配置：host、port、database、username、encrypted_password
     - 性能参数、部署元数据、状态、时间戳
   - 部署器在成功部署后自动保存组件配置
   - 组件密码从 Kubernetes Secrets 获取，使用租户公钥加密后存储

3. **认证与授权**：
   - 实现基于 JWT 的认证
   - 支持 OAuth2/OpenID Connect
   - 验证每个端点的用户权限
   - 处理令牌刷新和过期

4. **资源管理**：
   - 策略：CRUD、部署、执行控制
   - 订单：查询订单历史、状态
   - 钱包：查询余额、持仓、账本
   - 回测：创建、查询、管理回测任务
   - 研究案例：用于 sigbot-researcher 集成

5. **API 文档**：
   - 生成 OpenAPI/Swagger 文档
   - 提供交互式 API 浏览器
   - 包含请求/响应示例
   - 记录认证要求

**编码指南**：

1. **API 设计**：
   - 严格遵循 RESTful 约定
   - 使用适当的 HTTP 方法（GET、POST、PUT、DELETE、PATCH）
   - 返回适当的 HTTP 状态码（200、201、400、401、403、404、500）
   - 对 API 进行版本控制（例如，`/api/v1/strategies`、`/api/v2/...`）
   - 对资源使用复数名词（`/strategies`、`/orders`）
   - 在适当时支持嵌套资源（`/strategies/{id}/backtests`）

2. **请求/响应处理**：
   - 使用 serde 进行请求/响应序列化
   - 在处理前验证请求负载
   - 返回一致的响应格式
   - 支持 JSON 和可能的其他格式（MessagePack 等）

3. **错误处理**：
   - 返回一致的错误响应格式：
     ```json
     {
       "error": {
         "code": "ERROR_CODE",
         "message": "Human-readable message",
         "details": {}
       }
     }
     ```
   - 使用适当的 HTTP 状态码
   - 包含用于程序化处理的错误代码
   - 记录带有完整上下文的 API 错误（user_id、tenant_id、endpoint、error）
   - 永远不要向客户端暴露内部错误详情

4. **认证**：
   - 实现认证中间件（tower middleware）
   - 从 Authorization header 提取 JWT 令牌
   - 验证令牌签名和过期时间
   - 从令牌声明中提取 user_id 和 tenant_id
   - 支持令牌刷新机制
   - 优雅地处理令牌过期（返回 401）

5. **授权**：
   - 实现授权中间件
   - 检查每个端点的用户权限
   - 支持基于角色的访问控制（RBAC）
   - 验证租户访问（用户只能访问其租户的数据）
   - 记录授权失败

6. **验证**：
   - 验证所有输入参数（path、query、body）
   - 使用 validator crate 或自定义验证
   - 清楚地返回验证错误（400 Bad Request）
   - 清理用户输入以防止注入攻击
   - 验证数据类型和范围

7. **多租户**：
   - 从 JWT 令牌或请求上下文中提取 tenant_id
   - 按 tenant_id 过滤所有查询
   - 防止跨租户数据访问
   - 支持租户特定的速率限制
   - 在所有操作中记录 tenant_id
   
   **租户加密与组件管理**：
   - 对于独占租户，管理加密密钥对以安全存储数据
   - 默认使用云托管密钥以防止数据丢失（可禁用）
   - 使用加密密码存储组件部署配置
   - 使用租户的公钥加密敏感数据（密码、交易所 API 密钥）
   - 支持在租户创建时导入或自动生成密钥对
   - 启用云管理时，私钥使用系统主密钥加密以用于恢复
   - 组件配置在部署后由部署器自动持久化

8. **分页与过滤**：
   - 支持分页（limit、offset 或基于游标）
   - 支持多字段过滤
   - 支持多字段排序
   - 在响应中返回分页元数据
   - 限制最大页面大小

9. **性能**：
   - 对所有端点使用异步处理器（Axum）
   - 实现按用户/租户的请求速率限制
   - 在适当时缓存响应（策略、配置）
   - 优化数据库查询（使用索引，避免 N+1）
   - 使用数据库连接池
   - 监控 API 延迟和吞吐量

10. **文档**：
    - 使用 utoipa 生成 OpenAPI 文档
    - 为所有端点记录描述
    - 包含请求/响应模式
    - 提供示例请求和响应
    - 记录认证要求
    - 保持 API 文档与代码同步
    - 生成交互式 Swagger UI

11. **安全**：
    - 验证和清理所有输入
    - 防止 SQL 注入（使用参数化查询）
    - 防止 XSS 攻击
    - 在生产环境中使用 HTTPS
    - 实现 CORS 策略
    - 速率限制以防止滥用
    - 记录安全相关事件

12. **测试**：
    - 为所有端点编写集成测试
    - 测试认证和授权
    - 测试多租户隔离
    - 测试错误场景（无效输入、未授权访问）
    - 测试分页和过滤
    - 使用测试夹具进行一致的测试
    - 模拟外部依赖（数据库、消息代理）

13. **配置**：
    - 支持基于环境的配置
    - 配置 API 服务器端口和主机
    - 配置 CORS 设置
    - 配置速率限制规则
    - 支持 API 端点的功能标志
