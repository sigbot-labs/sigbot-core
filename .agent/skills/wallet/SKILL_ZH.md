您正在开发钱包管理器模块 (SigbotWalletServer)。该微服务管理钱包余额、持仓和权益快照。

**架构与职责**：
- **2.1.5 钱包管理器**： 
  - 订阅来自 EMQX (ISigbotMessagerClient) 的交易信号结果
  - 在事务中更新 s_ledger、s_balance、s_position、s_equity_snapshot 实体/表
  - 运行异步任务以定期从交易所 API 同步持仓/余额数据到数据库（用于离线对账和账户管理）

**主要职责**：
1. **交易事件处理**：
   - 订阅来自 EMQX 的交易结果主题（TOPIC_TRADING_RESULTS）
   - 解析 `SigbotTradeEvent` 消息
   - 按事务顺序处理交易事件

2. **账本管理**：
   - 使用交易记录更新 `s_ledger` 表
   - 实现复式记账
   - 确保事务原子性

3. **余额更新**：
   - 原子性地更新 `s_balance` 表
   - 正确处理并发余额更新
   - 支持多币种余额

4. **持仓跟踪**：
   - 使用当前持仓更新 `s_position` 表
   - 跟踪每个符号的持仓变化
   - 计算未实现盈亏

5. **权益快照**：
   - 定期更新 `s_equity_snapshot` 表
   - 在特定时间点捕获权益
   - 支持历史权益分析

6. **交易所同步**：
   - 定期异步任务从交易所 API 同步持仓/余额
   - 将本地数据库与交易所数据对账
   - 检测并记录差异
   - 支持离线对账

**编码指南**：

1. **消息驱动架构**：
   - 使用 tokio::spawn 异步处理交易事件
   - 优雅地处理事件反序列化错误
   - 记录所有接收的事件及其上下文（trade_id、order_id、tenant_id）
   - 支持带适当排序的并发事件处理

2. **事务管理**：
   - 对原子更新使用数据库事务
   - 在单个事务中更新 s_ledger、s_balance、s_position
   - 正确处理事务回滚
   - 对幂等性使用 ON CONFLICT 子句

3. **幂等性**：
   - 使用数据库 ON CONFLICT 处理重复事件
   - 跟踪已处理的事件 ID 以防止重新处理
   - 优雅地处理消息重新传递
   - 确保至少一次处理语义

4. **余额管理**：
   - 对余额更新使用原子数据库操作
   - 实现复式记账原则
   - 处理与交易所数据的余额对账
   - 跟踪余额历史以进行审计跟踪

5. **多币种支持**：
   - 支持多种加密货币和法币
   - 正确处理货币转换
   - 对精确计算使用小数类型（对货币避免使用 f64）
   - 一致地存储货币代码

6. **交易所同步任务**：
   - 使用分布式锁防止并发同步任务
   - 从交易所 API 查询当前持仓/余额
   - 与本地数据库状态比较
   - 记录差异以供手动审查
   - 使用交易所数据更新数据库

7. **错误处理**：
   - 使用指数退避实现重试逻辑
   - 优雅地处理数据库错误
   - 记录带有完整上下文的错误
   - 在临时失败时不丢失交易事件
   - 支持失败事件的死信队列

8. **安全**：
   - 永远不要记录敏感信息（私钥、密码、余额）
   - 对 ID 使用安全随机数生成
   - 实现适当的访问控制
   - 加密静态敏感数据

9. **性能**：
   - 优化数据库查询（使用索引）
   - 在可能时批量数据库更新
   - 使用连接池
   - 监控处理延迟
   - 缓存频繁访问的数据

10. **测试**：
    - 使用模拟事件测试交易事件处理
    - 测试事务原子性
    - 测试并发余额更新
    - 测试幂等性（重复事件）
    - 测试交易所同步逻辑
    - 测试错误场景（数据库失败、网络问题）
