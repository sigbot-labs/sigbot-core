您正在开发数据源接入模块 (SigbotDatafeedIngestor)。该微服务负责从外部源获取/订阅市场和新闻数据，并发布到 EMQX 消息代理。

**架构与职责**：
- **数据源接入器**：从外部 API（Binance、Twitter、TruthSocial、Coinmarketcap 等）获取市场/新闻数据，并发布到 EMQX (ISigbotMessagerClient) 作为交易工作流的第一步（策略分析之前的实时事件驱动中间件）

**主要职责**：
1. **外部数据获取**：
   - 从交易所 API（Binance 等）获取市场数据
   - 订阅实时市场流（websockets、REST API）
   - 从社交媒体 API（Twitter、TruthSocial）获取新闻数据
   - 并发处理多个数据源

2. **数据规范化**：
   - 将不同来源的数据规范化为通用格式
   - 将时间戳转换为 UTC
   - 标准化符号格式
   - 在发布前验证数据完整性

3. **消息发布**：
   - 将规范化数据发布到 EMQX 主题（TOPIC_MARKET_STREAMS）
   - 使用适当的 MQTT QoS 级别以确保可靠性
   - 使用重试逻辑处理发布失败
   - 支持市场数据和新闻数据流

**编码指南**：

1. **外部 API 集成**：
   - 实现速率限制以遵守 API 限制
   - 处理 API 认证（API 密钥、OAuth 令牌）
   - 实现指数退避重试
   - 为 HTTP 客户端使用连接池
   - 支持 REST 和 WebSocket 连接

2. **数据源抽象**：
   - 对不同数据源使用工厂模式
   - 为所有源实现 `ISigbotDatafeedClient` trait
   - 支持可插拔的数据源实现
   - 处理特定于源的错误类型

3. **消息代理集成**：
   - 使用 `ISigbotMessagerClient` trait 进行消息发布
   - 根据数据类型发布到适当的主题
   - 确保消息序列化高效（JSON）
   - 优雅地处理消息代理连接失败

4. **错误处理**：
   - 将外部 API 错误映射到内部错误类型
   - 记录带有完整上下文的错误（源、时间戳、数据）
   - 对失败的源实现熔断器模式
   - 如果一个源失败，继续操作

5. **性能**：
   - 对所有 I/O 操作使用 async/await
   - 并发处理多个数据源
   - 在适当时批量消息
   - 监控数据摄取延迟

6. **数据质量**：
   - 在发布前验证数据
   - 优雅地处理缺失或损坏的数据
   - 记录数据质量指标
   - 支持数据过滤/转换

7. **测试**：
   - 在单元测试中模拟外部 API
   - 测试数据规范化逻辑
   - 使用模拟代理测试消息发布
   - 测试错误场景（API 失败、网络问题）
   - 测试并发数据源处理

8. **配置**：
   - 支持每个源的配置
   - 允许启用/禁用特定源
   - 配置重试策略和超时
   - 支持环境特定设置
