您正在开发通知转发器模块 (SigbotNotificationForwarder)。该微服务订阅来自 EMQX 的通知消息，并将它们转发到各种渠道。

**架构与职责**：
- **2.1.6 通知转发器**：订阅来自 EMQX (`ISigbotMessagerClient`) 的通知消息，并根据通知类型将它们转发到 Email、Telegram、微信和其他平台

**主要职责**：
1. **消息订阅**：
   - 订阅来自 EMQX 的通知主题
   - 处理不同的通知类型（交易警报、系统通知等）
   - 解析通知消息并提取路由信息

2. **多渠道转发**：
   - 转发到 Email (SMTP)
   - 转发到 Telegram (Bot API)
   - 转发到微信 (微信 API)
   - 支持可扩展的渠道架构

3. **通知路由**：
   - 根据用户偏好路由通知
   - 支持每个通知的多个渠道
   - 处理特定于渠道的格式化

**编码指南**：

1. **渠道抽象**：
   - 使用基于 trait 的设计（`ISigbotNotificationClient`）
   - 实现用于渠道创建的工厂模式
   - 支持可插拔的渠道实现
   - 处理特定于渠道的配置

2. **消息处理**：
   - 从 JSON 反序列化通知消息
   - 验证通知结构
   - 提取接收者信息
   - 为目标渠道格式化消息

3. **错误处理**：
   - 优雅地处理渠道失败（不要阻塞其他渠道）
   - 使用指数退避重试失败的通知
   - 记录带有上下文的通知失败
   - 支持失败通知的死信队列

4. **速率限制**：
   - 遵守渠道速率限制（例如，Telegram API 限制）
   - 实现每个渠道的速率限制
   - 在超过速率限制时排队通知
   - 监控速率限制使用

5. **安全**：
   - 永远不要记录敏感的通知内容
   - 加密凭据（API 密钥、令牌）
   - 验证通知来源
   - 支持渠道的认证

6. **性能**：
   - 异步处理通知
   - 在可能时批量通知
   - 为 HTTP 客户端使用连接池
   - 监控通知传递延迟

7. **测试**：
   - 在测试中模拟通知渠道
   - 测试消息路由逻辑
   - 测试错误场景（渠道失败）
   - 测试速率限制行为
   - 测试并发通知处理

8. **配置**：
   - 支持每个渠道的配置
   - 允许启用/禁用特定渠道
   - 配置重试策略
   - 支持通知模板
