您正在开发订单管理器模块 (SigbotOrderServer)。该微服务订阅交易信号，并通过交易所客户端 SDK 执行订单。

**架构与职责**：
- **订单管理器**：订阅来自 EMQX (ISigbotMessagerClient) 的交易信号，调用交易所客户端 SDK 放置/取消/修改订单，并将交易信号结果发布回 EMQX

**主要职责**：
1. **信号订阅**：
   - 订阅来自 EMQX 的交易信号主题（TOPIC_TRADING_SIGNALS）
   - 解析 `SigbotTradeSignal` 消息
   - 处理通配符主题订阅（多租户支持）

2. **订单执行**：
   - 通过交易所客户端 SDK 放置订单
   - 取消挂单
   - 修改现有订单
   - 处理不同的订单类型（市价、限价、止损等）

3. **结果发布**：
   - 将交易结果（`SigbotTradeEvent`）发布到 EMQX (TOPIC_TRADING_RESULTS)
   - 包含订单状态、成交和执行详情
   - 确保至少一次传递语义

**编码指南**：

1. **消息驱动架构**：
   - 使用 tokio::spawn 异步处理信号
   - 优雅地处理信号反序列化错误
   - 记录所有接收到的信号及其上下文（signal_id、tenant_id）
   - 支持并发信号处理

2. **交易所集成**：
   - 通过工厂模式使用交易所客户端 SDK
   - 处理特定于交易所的错误类型
   - 将交易所响应映射到内部类型
   - 支持多个交易所（CEX、DEX）

3. **订单生命周期**：
   - 对订单状态使用状态机模式
   - 跟踪订单历史和状态转换
   - 正确处理部分成交
   - 支持订单修改和取消

4. **并发与线程**：
   - 对订单状态更新使用原子操作
   - 为订单修改实现适当的锁定
   - 处理订单执行中的竞争条件
   - 并发处理订单但保持每个符号的顺序

5. **错误处理**：
   - 优雅地处理交易所拒绝
   - 为临时失败实现重试逻辑（网络问题）
   - 记录带有完整上下文的订单失败（signal_id、order_id、error）
   - 将错误事件发布到通知系统
   - 不要重试永久失败（无效订单、余额不足）

6. **持久化**：
   - 将订单持久化到数据库以进行恢复
   - 对订单操作使用事务
   - 实现订单重放机制
   - 存储订单执行历史

7. **测试**：
   - 测试信号订阅和解析
   - 使用模拟交易所客户端测试订单执行
   - 测试订单状态转换
   - 验证并发订单处理
   - 测试订单持久化和恢复
   - 测试错误场景（交易所失败、网络问题）

8. **性能**：
   - 优化低延迟订单执行
   - 为交易所客户端使用连接池
   - 在可能时批量订单操作
   - 监控订单执行延迟
