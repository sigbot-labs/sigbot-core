# Authguard migration and Helm ownership

Authguard owns authentication, accounts, sessions and grants. Sigbot retains business tenant bindings and accepts only the official SDK's verified, bounded-lifetime request context. The integration pins `authguard-adapter-rust` to commit `56f00ee51a33136dae7e83beba558cdbf05c4a85`. `HeaderAccessContextResolver` verifies the Authguard HMAC signature and expiry; `GrpcAccessContextResolver` resolves opaque scope tokens. Sigbot does not call the SDK's thread-local context functions. Each HTTP request carries a `RequestIdentity` in Axum extensions, and each business handler receives that identity explicitly.

The old local login, JWT issuance, OAuth callbacks, user CRUD, user repositories and process-global `SecurityContext` have been removed. Existing identity tables remain migration sources; they are not an active IAM implementation. Export and reconcile their users into Authguard using the operator's approved identity mapping before routing production users. Old Sigbot JWTs are no longer accepted. Configure the browser's same-origin `/auth/login`, `/auth/account/security` and `POST /auth/logout` routes through Authguard; do not forward those paths to the Sigbot API.

`authguard` is the typed Sigbot runtime configuration. `provider` is `signed_header` or `grpc`; `service`, `partition`, `region`, `read_action` and `write_action` bind the signed context to the API request. The defaults expect `urn:iam:default:sigbot:global:<tenant>:<request-path-without-leading-slash>` and `sigbot:read` for GET/HEAD, `sigbot:write` for other methods. Configure matching Authguard route policies. A supplied `x-sigbot-tenant-id` must match the signed tenant. Deny grants override allows. Trust cannot be established by supplying an unsigned identity header.

Pass `AUTHGUARD__AUTHZ__SCOPE_DELIVERY__DIRECT_CONTEXT_HMAC_KEY` through a Secret shared with Authguard AuthZ for signed-header delivery. For gRPC use the SDK's `AUTHGUARD_GRPC_TARGET` and `AUTHGUARD_GRPC_TLS` settings and restrict backend network access to the Gateway/workloads. The API refuses to bind without a valid verifier configuration. Worker-only states install a deny-all provider when no verifier is configured, so they do not need Gateway signing keys. No secret values are stored in the chart. Business tenant key custody additionally requires `SIGBOT_SYSTEM_MASTER_KEY`; the previous default master key and JWT-secret fallback are removed.

Workflow APIs are available at `/api/v1/workflows`, `/api/v1/workflows/{id}`, and `POST .../{id}/start` / `stop`. Queries derive `tenant_id` from the authenticated context. A create request supplies a positive `space_id` and an environment (`live`, `paper`, `simulated`, `backtest`); subsequent updates cannot change those isolation fields. Responses exclude secret configuration. Start atomically records the immutable graph snapshot in `workflow_run` and marks the workflow pending for the embedded shared controller. Repeated start returns the same active run. Acceptance is not deployment completion or a trade acknowledgement. Migrated `legacy` workflows remain non-runnable until explicitly bound by migration. Raw unscoped workflow queries/deletions fail closed. A worker must receive `authguard.service_tenant_id`, `service_space_id`, `service_env` and `service_principal_id` explicitly; absent service identity cannot scan all tenants.

The Helm chart preserves existing top-level module locations. `systemdb` is the single PostgreSQL process with TimescaleDB and vector extensions; its image must include both libraries. The extension init script applies to newly initialized databases; apply `CREATE EXTENSION IF NOT EXISTS timescaledb; CREATE EXTENSION IF NOT EXISTS vector;` as a database administrator when upgrading an existing volume. Before disabling the historical `pgvector` database, migrate its embedding data into `systemdb`; enabling that old gate now fails with a migration message. MinIO stores durable log chunks. Shared Rust libraries do not receive standalone Deployments.

`authguard-middleware.enabled` defaults to false. The vendored official OCI dependency is Authguard **1.0.2**, registry digest `sha256:41423ab9646d3dd7c119d4995a5fb335551d17282d8961f245b05ba81f1f813e`; `Chart.lock` is generated by Helm. The middleware is installed as a separate explicit release with the Sigbot server gate disabled. Normal Sigbot releases leave the dependency gate disabled. The child chart's own Authguard value hierarchy remains unchanged beneath the dependency alias.

Before installation, use `tooling/deploy/helm/sigbot/bootstrap/kubernetes-secrets-setup` with explicit namespace and local Secret env-file paths. Never commit populated env files. PostgreSQL and Redis application credential fields must match their corresponding middleware credential fields. Rotating the runtime Secret requires incrementing `secrets.revision` so pods restart. Bootstrap failure aborts installation; values contain only Secret references.

The real public application hostname is an operator input, not an invented default. Set `server.gateway.hostnames`, the Authguard Application hosts/HTTPS return URIs and AuthN/Web route hostnames to the same actual origin. Configure cross-namespace Gateway `allowedRoutes` and reference grants when needed. No production hostname or cluster is guessed. The default chart and the explicit middleware-enabled chart pass the skill's render validator without an Application binding; Hosted Login/protected-route browser smoke requires the supplied real domain and a designated deployment target.

Verification commands:

```bash
helm lint tooling/deploy/helm/sigbot
HTTPS_PROXY=http://127.0.0.1:8800 python3 ~/authguard/.agents/skills/authguard-chart-integrator/scripts/validate.py \
  --chart tooling/deploy/helm/sigbot --set server.enabled=false
cargo test -p sigbot-core --test authguard_integration --test scoped_query --test config_loader
```

The Rust tests cover concurrent request identity isolation, valid signed contexts, invalid signatures, expiry, action/path/tenant mismatch, deny precedence and numeric tenant binding in real SQLite queries. A build or E2E report, rather than this command list, is the evidence that the tests passed in a particular environment.

Configuration is now canonical `snake_case`, with old kebab-case file keys normalized before defaults merge. Duplicate canonical keys fail. Environment variables retain the `SIGBOT__` hierarchy, and `${VARIABLE:default}` placeholders are resolved without a shell. Unknown typed keys are rejected. Flattened legacy blocks retain their compatibility representation; all new worker/Authguard blocks are strict.

The UI domain APIs additionally require domain grants under `environment/<env>/space/<space>/{overview,market,connection,notification}/all`; Workflow checks the concrete ID or `new`. This is checked against the SDK's allow/deny patterns in addition to the signed HTTP path grant. Give an operator the explicit domain grants required by that role; a valid session alone is not access to every space.

Apply `tooling/deploy/migrations/migrate.py` using the database owner's migration credentials before starting the API. Runtime PostgreSQL connections use typed connection options, the configured pool limits, schema and SSL policy; they do not create databases or run DDL. Startup checks that the migration ledger and Workflow tables exist. Runtime credentials should have only the required DML privileges.

`cargo test -p sigbot-core --test authenticated_workflow_api -- --ignored` requires the dedicated migrated `MARKETPULSE_DATABASE_URL`. It starts a real TCP API, signs contexts with the official Authguard SDK, checks tenant/space/deny isolation against PostgreSQL, and verifies transactional repeated-start behavior. This trusted-gateway boundary test does not replace Hosted Login browser acceptance or actual worker deployment acceptance.

`deployer.enabled` enables the shared controller inside the API host and grants only namespaced Deployment/NetworkPolicy operations. Set its explicit `deployer.scope` and egress ranges. `secrets.worker_existing_secret` identifies a separate host Secret without Gateway verifier keys; bootstrap can create it from `SIGBOT_WORKER_SECRET_ENV_FILE`. The UI server and shared libraries do not gain an independent deployment for this controller. See `src/deployer/README.md` for operational bounds and `src/web/README.md` for real browser gates.
